# CLAUDE.md — 勤怠・給与計算・労務手続き管理システム

従業員10名前後の会社（人材紹介業）向けの、打刻・勤怠集計・給与計算・労務手続きのタスク管理を行う社内Webシステム。
利用者は総務・経理の担当者（管理画面）と従業員（打刻画面）。画面・メッセージ・コメントはすべて日本語。

## 構成
- Node.js（20以上）+ Express 4 + EJS + better-sqlite3（SQLite 1ファイル）
- `src/server.js`：全ルート（打刻、従業員、勤怠、給与、タスク、算定基礎、CSV出力、設定、バックアップ/復元、操作ログ）
- `src/db.js`：スキーマ定義と接続（復元時に接続を差し替えるためラッパー経由で使う。`require('better-sqlite3')` を他所で直接開かない）
- `src/settings.js`：料率などの設定項目の定義（画面から変更し、DBの settings テーブルに保存）
- `src/lib/`：計算ロジック（純粋関数。DBに依存しない）
  - `attendance.js` 日次・月次の勤怠計算、36協定チェック
  - `payroll.js` 給与計算、社会保険料の端数処理、介護保険の対象判定
  - `withholding.js` 源泉所得税（甲欄・電算機計算の特例）
  - `standardRemuneration.js` 標準報酬月額表
  - `leave.js` 有給の付与・残日数・年5日義務
  - `procedures.js` 入退社・年次タスクの生成、月額変更届（随時改定）の判定、算定基礎の試算
  - `dates.js` 日付ユーティリティ（'YYYY-MM-DD' 文字列、UTC計算。現在時刻は `nowJst()`）
- `test/calc.test.js`：計算ロジックのテスト（`npm test`）
- `render.yaml`（リポジトリ直下）：Render へのデプロイ設定。手順は `DEPLOY.md`

## 開発ルール
- 計算ロジックを変更したら必ず `test/calc.test.js` にテストを追加し、`npm test` を通すこと。給与の計算結果を変える変更は、変更前後の差額を説明できるようにする
- 金額は円の整数。社会保険料の被保険者負担は「50銭以下切捨て・50銭超切上げ」（`employeeShare`）。浮動小数で端数判定しない
- 勤怠月（`ym`）と支給月（`pay_ym`）を区別する。住民税・源泉税の年分・算定基礎・随時改定は支給月基準
- 勤怠修正・給与確定/取消・設定変更・CSV出力・復元などの操作は `audit()` で操作ログに残す
- 確定済み（status='確定'）の給与は再計算で上書きしない
- マイナンバーは保持しない（安全管理措置の対象になるため）
- 管理画面は Basic 認証（`ADMIN_PASSWORD`）。本番（`NODE_ENV=production` または Render 上）ではパスワード未設定だと管理画面を開けない。打刻画面 `/punch` のみ認証なし（社員番号＋PIN、総当たり時はロック）
- 社会保険・労働保険の書類作成・提出の代行機能は作らない（社労士法27条。報酬を得て代行できるのは社会保険労務士のみ）。本システムは手続きの要否と期限の管理まで

## 毎年の保守作業（法改正・料率改定）
| 時期 | 作業 |
|---|---|
| 12月頃 | 翌年分の源泉所得税：国税庁「電子計算機等を使用して源泉徴収税額を計算する方法」の翌年分を確認し、`src/lib/withholding.js` の `PARAMS` に年分を追加。テストも追加 |
| 2〜3月 | 協会けんぽ（都道府県支部）の健康保険料率・介護保険料率（3月分〜）を確認し、設定画面で更新 |
| 3〜4月 | 雇用保険料率（4月〜）、子ども・子育て支援金率を確認し、設定画面で更新 |
| 随時 | 標準報酬月額表の等級改定があれば `standardRemuneration.js` を更新 |
