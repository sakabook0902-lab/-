# クラウド公開・アカウント移行の手順

このシステムを [Render](https://render.com) に公開して、**URLを開くだけで使える**ようにする手順です。
ここでは、まず自分（アンカー）のアカウントで公開して動作を確認し、その後に株式会社ニジ看護転職のアカウントへ引っ越す流れを説明します。

## 費用の目安

| 項目 | 内容 |
|---|---|
| サーバー（Starterプラン） | 月額 約7ドル |
| データ保存用ディスク（1GB） | 月額 約0.25ドル |
| 合計 | **月額 約1,100〜1,300円**（為替により変動。料金は変わることがあるため、契約前にRenderの料金ページで確認してください） |

無料プランはデータ保存用ディスクが使えず、再起動のたびにデータが消えるため使えません。

## A. 自分のアカウントで公開する（所要 15〜20分）

### 1. Renderのアカウントを作る
1. https://render.com を開き「Get Started」から **GitHubアカウントで登録** します。
2. 有料プランを使うため、Billing でクレジットカードを登録します。

### 2. Blueprint で構築する
1. Renderのダッシュボードで **New → Blueprint** を選びます。
2. リポジトリの一覧から `sakabook0902-lab/-` を選びます。表示されない場合は「Configure GitHub」からRenderにリポジトリへのアクセスを許可します。
3. ブランチは `claude/affectionate-davinci-bsc74z` を選びます（mainにマージ済みならmainで構いません）。
4. リポジトリ直下の `render.yaml` が読み込まれ、`roumu` というサービスが表示されます。
5. **ADMIN_PASSWORD** の入力欄に管理者パスワードを入れます。
   - 12文字以上で、英大文字・小文字・数字・記号を混ぜてください。給与と個人情報を守るための唯一の鍵になります。
   - このパスワードはRenderの画面にだけ保存され、リポジトリには残りません。
6. **Apply** を押すと構築が始まります（3〜5分）。

> デモ用の架空データを入れたい場合は、構築後に Environment で `SEED_DEMO` を `true` にして再デプロイします（データが空のときだけ投入されます）。本番では `false` のままにしてください。

### 3. 開いて確認する
1. サービスの画面上部に `https://roumu-xxxx.onrender.com` のようなURLが出ます。
2. URLを開くとログイン画面が出るので、ユーザー名 `admin`、パスワードは手順2-5で設定したものを入力します。
3. **打刻用のURL** は `https://roumu-xxxx.onrender.com/punch` です。打刻画面だけはログインなしで開けます（社員番号＋PINで本人確認）。
   - 従業員には、このURLをスマホの「ホーム画面に追加」してもらうと、アプリのように使えます。

### 4. 初期設定
1. **設定** 画面で、「要確認」の料率を公式資料（協会けんぽ・厚生労働省）で確認して保存します。
2. **従業員** 画面で従業員を登録します（標準報酬月額・住民税・扶養人数も入力）。
3. 給与は2〜3ヶ月、既存の方法と並行して計算し、結果が一致することを確認してから本番に切り替えます。

### 更新（プログラムを直したとき）
GitHubの対象ブランチにpushすると、Renderが自動で再構築します。データ（ディスク）はそのまま残ります。

## B. ニジ看護転職のアカウントへ引っ越す

給与・個人情報の持ち主は客先なので、本番運用はニジ看護転職のアカウントで行うのが安全です。

### 1. 客先側で用意するもの
- 会社のGitHubアカウント（Organizationを推奨）
- 会社のRenderアカウント（支払いは会社のクレジットカード）
- 会社のClaude Code（GitHub連携済み）

### 2. プログラムを客先のリポジトリへコピーする
⚠ **今のリポジトリ（`sakabook0902-lab/-`）をそのまま移譲・共有しないでください。** 他の案件のファイルが入っているためです。`roumu` フォルダと `render.yaml` だけをコピーします。

1. 客先のGitHubで、空の **Private** リポジトリを作ります（例：`roumu-system`）。
2. 自分のパソコンで、次を順に実行します（`<客先のリポジトリURL>` は手順1で作ったもの）。

```bash
git clone --branch claude/affectionate-davinci-bsc74z https://github.com/sakabook0902-lab/-.git anchor-src
```

```bash
mkdir roumu-system && cp -r anchor-src/roumu anchor-src/render.yaml roumu-system/
```

```bash
cd roumu-system && git init -b main && git add . && git commit -m "勤怠・給与・労務システム 初期移行"
```

```bash
git remote add origin <客先のリポジトリURL> && git push -u origin main
```

> コマンド操作が難しい場合は、Claude Codeに「`roumu` フォルダと `render.yaml` だけを新しいリポジトリにコピーして」と依頼しても構いません。

### 3. 客先のRenderで構築する
客先のRenderアカウントで、上の **A-2〜A-3** と同じ手順を行います（リポジトリは客先のもの、ブランチは `main`）。
ADMIN_PASSWORD は**新しく別のもの**を設定し、客先の管理者に安全な方法（口頭・パスワード管理ツール等）で渡します。

### 4. データを移す
1. 移行日を決め、その時間帯は打刻を止めてもらいます（給与確定の直後がおすすめ）。
2. **旧システム**：設定 → **バックアップをダウンロード**
3. **新システム**：設定 → 復元 → ダウンロードしたファイルを選んで **このファイルで復元**
4. 新システムで、従業員数・直近の勤怠・給与・タスクが揃っていることを確認します。
5. 従業員に**新しい打刻URL**を案内します（ホーム画面のショートカットも作り直してもらいます）。

### 5. 旧環境を片付ける
1. 新システムで数日問題がないことを確認します。
2. 自分のRenderで `roumu` サービスを **Delete** します（ディスク上のデータも消えます）。
3. 手元にダウンロードしたバックアップファイルを削除します。

### 6. 客先のClaude Codeで使う
客先のClaude Codeで新しいリポジトリを開くと、`roumu/CLAUDE.md` が自動で読み込まれ、システムの構成・注意点・毎年の保守作業がClaude Codeに伝わります。
「令和9年分の源泉所得税の計算式に更新して」「賞与計算を追加して」などと依頼すれば、その前提で作業できます。

## 個人情報の取り扱い（移行前の注意）
自分のアカウントで本物の従業員データを扱う期間は、客先の個人情報を預かる状態になります。業務委託契約に、秘密保持・個人情報の取り扱い（保管場所、契約終了時の返還・削除）が定められているか確認してください。動作確認の段階では、架空のデモデータ（`SEED_DEMO=true`）で行うのが安全です。
