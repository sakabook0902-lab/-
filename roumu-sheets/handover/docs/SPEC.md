# 仕様書：勤怠・給与・労務システム

## 1. 目的と前提
| 項目 | 内容 |
|---|---|
| 目的 | 勤怠・給与計算・労務手続きを1つの仕組みで行い、手作業と手続き漏れを減らす（人事労務freeeのような使い勝手） |
| 会社 | 株式会社ニジ看護転職（有料職業紹介業）。従業員10名前後、拠点は五反田・赤坂・リモート |
| 給与の特徴 | 月給制。固定残業代あり。成約インセンティブ（歩合給）あり |
| 動作環境 | Googleスプレッドシート＋Google Apps Script（Webアプリ）。サーバー代0円 |
| 利用者 | 従業員（マイページ）、総務・経理（管理画面） |
| 法令上の線引き | 届出書類の作成・提出は会社の社員が自社の分を行う。報酬を得て他社の届出を代行するのは社会保険労務士の独占業務（社労士法27条）のため、その用途の機能は作らない |
| 個人情報 | マイナンバーは保持しない。スプレッドシートの共有は総務・経理のみ。従業員はWebアプリ経由でのみ利用 |

## 2. 画面と機能
1つのURL（Webアプリ）で、ログインした人に応じて画面が切り替わる。

### 2-1. ログイン
- 会社のGoogleアカウント：従業員シートの「Googleアカウント」と一致すれば自動ログイン（PIN不要）
- 従業員：社員番号＋PIN（4〜8桁）。同じ社員番号で5回失敗すると15分ロック
- 管理者：スプレッドシートのオーナー、設定「管理者のGoogleアカウント」に登録した人、または管理者パスワード（SHA-256で保存、5回失敗で15分ロック）
- セッションは6時間（CacheService）

### 2-2. 従業員マイページ
| 画面 | 内容 |
|---|---|
| 打刻・ホーム | 出勤・退勤・休憩開始・休憩終了、勤務場所。日付をまたぐ勤務は前日分として記録。今月の出勤日数・実働・時間外・有給残日数、最新の明細 |
| 勤怠 | 日別の出退勤・実働・時間外・深夜（閲覧のみ。修正は総務に依頼） |
| 給与明細 | 確定済みの給与明細・賞与明細の閲覧・印刷（本人の分のみ） |
| 有給休暇 | 残日数、年5日の取得状況、付与・取得の履歴 |

### 2-3. 管理画面
| 画面 | 内容 |
|---|---|
| ダッシュボード | 期限が近い労務手続き（書類ボタン付き）、36協定アラート、有給5日義務、本日の打刻、退勤打刻漏れ、未確定の給与 |
| 従業員 | 登録・編集・退職登録。登録で入社手続きタスク、退職で退職手続きタスクを自動作成。固定的賃金の変更を自動検知して賃金変更履歴に記録 |
| 勤怠 | 月次集計（時間外・60時間超・法定休日・深夜・打刻漏れ・36協定）、日別の修正（操作ログに記録） |
| 給与計算 | インセンティブ・欠勤・その他手当／控除・源泉税手入力・年末調整過不足を入力 → 計算 → 確定（取消は理由必須）→ 明細PDF・メール送信（同意者のみ）→ 全銀振込データ・給与仕訳CSV |
| 賞与 | 賞与額・源泉の算出率を入力 → 計算 → 確定（賞与支払届タスク作成）→ 明細PDF・振込データ・仕訳CSV |
| 年末調整 | 給与・賞与・社会保険料・源泉税を自動集計 → 申告書の内容を入力して計算 → 12月支給の給与に過不足を反映 |
| 労務タスク | 期限順の一覧、状態（未対応／対応中／完了）とメモ、手動追加、書類ボタン |
| 届出書類 | 記入内容シート（PDF）9種類（2-4参照） |
| 設定 | 会社情報、労働時間、36協定、社会保険料率、通知、管理者、振込元口座、仕訳の勘定科目 |
| 操作ログ | ログイン、勤怠修正、給与確定・取消、設定変更、書類作成などの記録 |

### 2-4. 届出書類（記入内容シート）
**正式な様式そのものではなく、正式様式の項目順にデータを当てはめた転記用のPDF**。期限・提出先・要記入の項目を表示する。
社会保険・雇用保険の資格取得届／喪失届、月額変更届（随時改定）、算定基礎届（定時改定）、賞与支払届、住民税の特別徴収切替届、給与所得者異動届（退職）。
- 雇用保険の喪失届には、離職証明書の「賃金支払状況」を作るための12ヶ月分の賃金を添付
- 住民税の異動届は、年税額・徴収済額・未徴収税額と徴収方法（1〜4月退職は一括徴収）を自動計算
- 住民税の様式は市区町村ごとに異なる

### 2-5. 自動化
- 毎朝8時台：ダッシュボードとタスクを更新し、期限が近い手続き・36協定・有給5日・打刻漏れをメール／Slackで通知
- 年次タスクを自動作成：住民税の通知書登録（5月）、労働保険の年度更新・算定基礎届（7/10）、年末調整（12月）、法定調書・給与支払報告書（1/31）、36協定の更新（期限30日前）
- 給与確定時に月額変更届の要否を判定してタスク化

## 3. 計算ルール（`roumu/src/lib`）
| 区分 | ルール |
|---|---|
| 勤怠 | 時間外＝1日8時間超＋週40時間超（週は日曜始まり）。法定休日は設定の曜日（初期値：日曜）。深夜＝22時〜翌5時（休憩は深夜から差し引かない）。月60時間超は割増50% |
| 36協定 | 月の時間外が上限（初期値45時間）の80%で注意、超過で警告。時間外＋休日労働が月100時間以上、2〜6ヶ月平均80時間超で警告 |
| 割増賃金 | 時間単価＝（基本給＋役職手当）÷月平均所定労働時間。時間外1.25（60時間超1.5）、法定休日1.35、深夜0.25。固定残業代は時間外割増に充当し、超過分を支給 |
| インセンティブ | 歩合給として扱い、歩合給÷総労働時間×割増率（0.25等）×時間外時間を割増として支給 |
| 欠勤控除 | （基本給＋役職手当）÷月平均所定労働日数×欠勤日数（切捨て）。月途中の入社・退職は日割せず「要確認」を表示 |
| 社会保険料 | 標準報酬月額×料率÷2、50銭以下切捨て・50銭超切上げ。介護保険は40歳到達月〜65歳到達月の前月。子ども・子育て支援金は設定の支給月から控除 |
| 雇用保険料 | 総支給額×労働者負担率（50銭以下切捨て） |
| 源泉所得税 | 甲欄：国税庁「電子計算機等を使用して源泉徴収税額を計算する方法」（令和8年分）。乙欄は手入力 |
| 住民税 | 6月支給分と7月〜翌5月支給分の月額を従業員ごとに登録 |
| 標準報酬月額 | 健保50等級・厚年32等級の表。未登録の場合は固定的賃金から仮計算 |
| 随時改定 | 固定的賃金の変更後3ヶ月の報酬平均で2等級以上の差、3ヶ月とも支払基礎日数17日以上 |
| 有給休暇 | 入社6ヶ月で10日、以降1年ごとに11・12・14・16・18・20日。2年で時効、古い付与分から消化。年5日の取得義務を追跡（比例付与・前倒し付与は未対応） |
| 賞与 | 標準賞与額＝1,000円未満切捨て。健保は年度累計573万円、厚年は1回150万円が上限。源泉は（賞与−社会保険料）×算出率（算出率は担当者が国税庁の表で確認して入力） |
| 年末調整 | 令和7年度改正後の給与所得控除（最低65万円、190万〜660万円は4,000円単位）、基礎控除（所得に応じ95万〜58万円等）、配偶者控除、扶養控除（一般38万・特定63万・老人48万・同居老親58万）。年税額＝算出税額×102.1%（100円未満切捨て）。配偶者特別控除・障害者控除などは手入力 |
| 全銀振込データ | 総合振込（種別21）、1レコード120桁、半角カナ、Shift_JIS・CRLF |

## 4. データ（スプレッドシートのシート）
「労務 → 初期設定」で自動作成される。列は**見出し名で対応付けている**ため、列の順番を入れ替えても動くが、見出し名は変えないこと。
ダッシュボード／設定／従業員／勤怠／有給取得／給与入力／給与／賞与／年末調整／労務タスク／賃金変更履歴／操作ログ／_賃金スナップショット（非表示）。
各シートの列の定義は `roumu-sheets/src/Code.js` の `SHEETS`、設定項目は `SETTING_DEFS` にある。

## 5. 未確認・要確認の事項（本番運用の前に必ず確認）
開発時にインターネット上の公式資料（国税庁・協会けんぽ）に直接アクセスできず、以下の数値は公式資料との照合が済んでいない。
| 項目 | 現在の値 | 確認先 |
|---|---|---|
| 健康保険料率（東京） | 9.85% | 協会けんぽ 東京支部 令和8年度保険料額表 |
| 介護保険料率 | 1.62% | 同上 |
| 子ども・子育て支援金率 | 0.23%（令和8年4月分〜） | 同上 |
| 雇用保険料率（労働者負担） | 0.5%（令和8年度） | 厚生労働省 |
| 源泉所得税の計算パラメータ | `withholding.js` の令和8年分 | 国税庁 令和8年分 電子計算機等を使用して源泉徴収税額を計算する方法（別表第一〜第四） |
| 年末調整の控除額 | `yearEnd.js` の令和8年分 | 国税庁 令和8年分 年末調整のしかた |

あわせて、**2〜3ヶ月は既存の方法（社労士・既存ソフト）と並行して給与計算し、結果が一致することを確認してから本番に切り替える**。

## 6. 今後の予定・未対応の機能
| 優先 | 内容 |
|---|---|
| 高 | **e-Gov連携 第1段階**：日本年金機構の「届書作成プログラム」に取り込めるデータを出力し、届書作成プログラムからGビズIDでe-Gov電子申請する（資本金1億円超の法人は算定基礎届・月額変更届・賞与支払届の電子申請が義務） |
| 中 | e-Gov連携 第2段階：e-GovのAPIと直接連携して送信（デジタル庁への外部連携API利用申請・接続テストが必要。認証はGビズIDのOAuth。パスワードは保持しない） |
| 中 | 源泉徴収票・給与支払報告書の作成、乙欄・日額表の自動計算 |
| 中 | 有給休暇・打刻修正・残業の申請と承認（ワークフロー） |
| 低 | 時給制（パート・アルバイト）、フレックス・変形労働時間制、有給の比例付与 |
| 低 | 正式様式への印字（各機関の様式PDFをドライブに置き、位置を合わせて印字） |

## 7. これまでの主な決定事項
- 画面方式：スプレッドシートの操作ではなく、Webアプリ中心（freeeのような画面）
- 届出書類：正式様式への印字ではなく「記入内容シート」方式（様式の取得と位置合わせの検証ができないため）
- 計算ロジックはNode.jsでテストできる純粋関数とし、ビルドでApps Script用の1ファイルにまとめる
- 日付・時刻・番号はシート上で文字列として保存（自動変換によるずれを防ぐ）
