# 反社チェックシステム（MVP）

社内の与信管理業務における反社会的勢力（反社）チェックを、申請〜自動一次スクリーニング〜外部データ照会結果の記録〜承認〜証跡管理〜再チェックリマインドまで一元管理するための社内システムです。

`docs/antisocial-check-system-proposal.md` の提案（ハイブリッド型：外部データ照会は維持しつつ、業務フローと証跡管理を内製化）を実装したものです。

## できること

1. **企業情報検索** — 企業名（＋都道府県・法人種別・資本金/従業員数レンジでの絞り込み）または法人番号を指定して、経済産業省の無料API「gBizINFO」から法人番号・本社所在地・代表者・資本金・従業員数・業種・設立年月日を自動取得。同名の別会社と混同しないよう、法人番号を直接指定して1社に絞り込むこともできる
2. **チェック依頼登録** — 企業情報検索の結果を引き継ぐか、取引先名称・代表者・所在地等を直接入力して登録すると、登録済みの自社ブラックリストと自動で名称照合（一次スクリーニング）を実施
3. **年商・連絡先・行政処分の有無の記録** — 年商は有価証券報告書提出企業（主に上場企業等）のみ財務情報として自動取得を試み、取得できない場合や連絡先・行政処分の有無は、EDINET・各省庁の行政処分公表ページ・SafeBiz等での確認結果を担当者が手動記録
4. **外部データ照会結果の記録** — SafeBiz（アリュクス）や官報検索、都道府県公表情報など、外部で確認した結果（シロ／要確認／クロ）と根拠を記録
5. **最終判定・承認** — 与信管理責任者が承認／否認／保留を確定。承認時は次回再チェック期限（1年後）を自動設定
6. **証跡（監査ログ）** — 誰が・いつ・何をしたかをすべての案件で自動記録
7. **再チェックリマインド一覧** — 承認済み案件のうち、再チェック期限が近い／超過したものを一覧表示
8. **ブラックリスト管理** — 自社で過去に取引謝絶・関係解消した先を登録・一覧

### 自動取得できる項目・できない項目（重要）

無料の公的API（gBizINFO）で自動取得できるのは **法人番号・商号・本社所在地・代表者・資本金・従業員数・業種・設立年月日** です。
**年商（売上高）は、有価証券報告書の提出義務がある企業（主に上場企業等）に限り、財務情報として自動取得できる場合があります。** 非上場の中小企業は多くの場合データがなく、その場合は手動確認になります。
**連絡先・過去の行政処分の有無は、無料の公的APIには存在しないため自動取得できません。** これらを自動取得できるかのように表示すると、誤った判断材料を与えてしまうため、本システムでは「要手動確認」として確認先リンクを案内したうえで、担当者が確認結果を記録する設計にしています。

## セットアップ・起動

```bash
cd app
npm install
npm start
```

起動後、ブラウザで `http://localhost:3000` を開いてください。データは `app/data/app.db`（SQLite）に保存されます（`.gitignore` によりリポジトリには含めません）。

### 企業情報検索機能を使う場合（任意）

1. https://info.gbiz.go.jp/hojin/APIManual から無料のAPIトークンを取得（個人利用ならメールアドレスと利用目的のみで申請可能）
2. `app/.env.example` を `app/.env` にコピーし、`GBIZINFO_API_TOKEN` に取得したトークンを設定
3. `npm run start:env` で起動（`.env` を読み込んで起動します）

トークン未設定のまま起動した場合、企業情報検索画面は「未設定」の案内を表示し、それ以外の機能（チェック依頼登録・承認・証跡管理等）は通常どおり利用できます。

> 補足：`src/services/gbizinfo.js` のレスポンス項目名（`corporate_number`, `capital_stock` 等）は公開情報をもとに実装していますが、実際のAPIレスポンスと差異がある場合は、取得したトークンで一度実際のレスポンスを確認し、`normalize()` 関数のキー名を調整してください。
